# An ordinary research question

Create and select a workspace, then find data and previous work:

```sh
uv run bio init workspace
uv run bio work new "What Pmp22 values are present in this rat Schwann experiment?"
uv run bio data search --feature Pmp22
uv run bio artifact search --text "Schwann expression"
uv run bio work search --text Pmp22
uv run bio data show ASSET_ID
```

The returned question path is your normal working directory. Read the source metadata and immutable file, choose a scientific method, and write a script in `scripts/`. Execute it using your existing environment and tools. Keep `LABBOOK.md` current, including unsupported interpretations and failed routes. The platform has no scientific code executor or mandatory analysis DSL.

Register a useful output with exact inputs and code:

```sh
uv run bio register workspace/questions/QUESTION_ID/outputs/prepared.parquet \
  --question QUESTION_ID --title "Rat Schwann source table" \
  --summary "Original source strings with row locators; no normalization" \
  --input ASSET_ID --code workspace/questions/QUESTION_ID/scripts/prepare.py \
  --parameters '{"preserve_strings":true}'
uv run bio work sync QUESTION_ID --summary "Prepared source strings; biological applicability remains question-local" --status completed
```

The convenience flags capture the installed environment and hash code. For precise selectors, custom environment identity, logical command, limitations, multiple roles, or reference hashes, use `bio register OUTPUT --manifest MANIFEST.json --question QUESTION_ID` instead. A manifest is a small provenance record:

```json
{
  "title": "Source-preserving prepared table",
  "summary": "Literal cell strings and source rows; no normalization",
  "kind": "parquet",
  "output_role": "prepared_table",
  "limitations": ["Gene-level values do not establish promoter output"],
  "derivation": {
    "inputs": [{"blob":"SOURCE_SHA256","source_identity":"ASSET_ID","role":"source_table","selector":{"representation":"entire supplied table"}}],
    "code": ["SCRIPT_SHA256"],
    "parameters": {"preserve_strings":true},
    "references": [],
    "environment": {"python":"EXACT_VERSION","lock_sha256":"LOCK_SHA256"},
    "command": ["python","{code}","{input}","{output}"]
  }
}
```

Register code/reference files using `bio object add FILE`. Actual run details, including exit code, belong in an event JSON passed to `bio work event QUESTION_ID --kind command --payload EVENT.json`. The artifact manifest preserves exact code; downloaded author code must never be executed automatically.

A second question can search for the artifact, inspect it, and reuse it:

```sh
uv run bio work new "What does the same table contain about Sox10?"
uv run bio artifact search --text "prepared table"
uv run bio artifact show ARTIFACT_ID
uv run bio artifact find --derivation DERIVATION.json --output-role prepared_table
uv run bio artifact use ARTIFACT_ID --question SECOND_QUESTION_ID --name prepared.parquet
uv run bio provenance ARTIFACT_ID
```

`DERIVATION.json` contains just the `derivation` object from the manifest. An exact match authorizes byte reuse, not a biological conclusion. A new selector, script, parameter, reference, or environment yields a different key. If the new question needs promoter-specific measurements or a different preprocessing choice, return to the source.

For fresh data, `bio resolve ACCESSION` inventories files, `bio fetch ASSET_ID` acquires one, and `bio inspect ACQUIRED_ASSET_ID` adds searchable structures and literal labels. Archive members can be selected with `bio data extract ARCHIVE_ID --member EXACT_MEMBER_NAME`. `bio discover "QUERY" --provider europepmc` provides an explicit bounded public-search fallback.
