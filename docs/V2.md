# Persistent research-data substrate

The product precomputes what data contains and preserves useful prior work. A stock coding agent decides what those facts mean for its current question. There is no embedded agent harness, scientific programming language, global accepted interpretation, or mandatory report UI.

## Four layers

```text
Stock coding agent: reasoning, normal scripts, scientific tools
                        │
bio: search / resolve / fetch / inspect / register / prior work
                        │
SQLite: research graph, profiles, questions, artifacts, task frontier
                        │
Immutable objects: source bytes, native files, code, references, results
```

Schema version 3 is an additive migration from v1 catalog versions 1/2. Existing files stay under `blobs/sha256/<prefix>/<hash>`; the conceptual v2 object store is the same store, avoiding duplicate copies or broken historical paths. `questions/` holds editable work. Profiles and work snapshots are immutable JSON objects with SQLite indexes. Alternative profile origins coexist; the latest profile per origin is a search projection, not scientific acceptance. No v1 evidence, source receipt, or interpretation is removed.

`bio init OLD_WORKSPACE` creates missing working directories and migrates the catalog under the parent writer lock. Back up first for rollback. Old software cannot open schema 3; restore the pre-migration backup to roll back. The current `daw` and `bio` commands can both use the migrated workspace.

## Progressive indexing

| Level | Indexed information | Boundary |
|---|---|---|
| 0 | Publications, repository identities, explicit relationships, source assertions | Bulk graph ingestion and source metadata; no biological identity merging |
| 1 | File names, sizes, checksums, raw/processed flags, sample/source context | Inventory is distinct from downloaded bytes |
| 2 | Native structures, sheets, axes/layers, interval metadata, literal feature labels | Bounded inspection, no normalization or inferred measured universe |
| 3 | Agent-authored context and apparent affordances with source citations | Descriptive alternatives, no approval state |

The default `bio index run` inventories existing assets and profiles acquired ones without network calls. It returns a persistent job ID. Continue with `bio index run --job ID`. `bio index status --job ID` exposes pending, blocked, partial, and deferred tasks; `--retry` explicitly retries terminal incomplete tasks. Provider-search cursors and recovered identities persist across bounded runs; repeated cursors remain partial instead of looping. An interrupted running task returns to pending on resumption. `bio recover` also requeues interrupted tasks.

For a bounded remote pass, save this configuration:

```json
{
  "seeds": [{"reference": "GSE201623"}],
  "include_existing": false,
  "level": 2,
  "fetch_processed": true,
  "extract_archives": true,
  "max_tasks": 100,
  "max_seconds": 300,
  "max_requests": 30,
  "max_download_bytes": 134217728,
  "max_asset_bytes": 67108864
}
```

```sh
uv run bio index run --plan workspace/index.json
uv run bio index status --job INDEX_ID
uv run bio index run --job INDEX_ID
uv run bio index schedule --plan workspace/index.json --every 86400
uv run bio index tick --max-feeds 1
```

Invoke `tick` periodically with cron, launchd, or your existing scheduler. Each call is bounded; a due feed drains its pending job before starting another inventory. Partial terminal outcomes remain visible and are refreshed on the next scheduled inventory. A job's `complete` state means its scheduled work finished, not that all public data or all listed raw files were acquired. Download budgets reset for each resumable invocation and the workspace's stricter bounds apply. Wall limits stop scheduling new tasks; an active task also has its own worker/transport limit. Metadata-only GEO indexing uses the native bounded transport, without launching GEOfetch outside that accounting.

Raw files stay listed; the indexer never downloads or processes them automatically. `bio fetch --allow-raw` is an explicit acquisition exception, not processing permission. Archives remain inventoried without extraction unless configured. Extracted source members retain parent hashes/selectors. Unsupported, oversized, and inaccessible files remain in the catalog.

### Bulk research graph

Feed a local JSONL export through `bio index import GRAPH.jsonl --max-records 1000`. Each line has `kind`, `provider`, `native_id`, optional `body`, `identifiers`, and explicit `relationships`:

```json
{"kind":"article","provider":"example","native_id":"paper1","body":{"title":"An unrelated research topic"},"identifiers":{"doi":["10.1234/example"]},"relationships":[{"relationship":"has_dataset","target":{"kind":"study","provider":"geo","native_id":"GSE201623"}}]}
```

The original export and exact source lines are preserved. Imports checkpoint their byte offset after each record; rerunning resumes. Later records can supply metadata for relationship placeholders. Identifiers are searchable source assertions, not permission to collapse experiments or donors. Provider-specific bulk-export conversion remains an ordinary script; there is no blanket public-data crawl hidden behind this command.

### Content search and coverage

```sh
uv run bio search Schwann
uv run bio data search --feature Pmp22 --provider geo
uv run bio data search "Schwann RNA" --min-level 3
uv run bio data show ASSET_ID
uv run bio data history ASSET_ID
```

Search returns compact summaries, exact IDs, coverage level, and source locators. `bio data show` supplies source metadata, profiles, relationships, and the immutable file path. Feature matching is a case-sensitive literal-label lookup; it performs no ortholog, alias, gene, or assembly inference. A one-token text query also includes exact indexed labels. Multiword text uses literal AND matching with FTS5 BM25 ranking. Structured filters and pagination bound output. Search defaults to current asset revisions; `bio search --include-historical` includes older representations.

Tabular profiling scans literal cells, including hidden workbook sheets, without executing formulas. A match can be a selected-list member or descriptive label; it does not prove measurement. Numeric cells remain in the source for ordinary code to read. H5AD profiling indexes supported string feature-axis fields and reports structures/layers without loading matrix values. A partial content scan remains marked partial even if format inspection succeeded. Inspect the profile's `content_index` scope and limits before using a missing hit. Native bigWig/Cooler profiles describe coordinates and structures; gene retrieval requires sourced coordinate context, not guessed mappings.

Feature filters match the structural document holding the labels. An independently authored level-3 profile is a separate search document; retrieve both through their shared subject. Source context attached to each profile is bounded to 24 related records per subject; `bio data show` and the catalog retain the underlying relationships. Multiple profiles can produce multiple results for one dataset.

### Semantic profiles and optional vectors

Add a small source-backed `Profile` JSON with `bio data profile --manifest FILE`. Set an attributable `origin`, `subject`, `title`, `summary`, descriptive `facts`, `apparent_affordances`, `limitations`, and evidence locators. The schema is in `contracts/profile.schema.json`. Level 3 requires resolvable evidence; it does not validate the scientific claims. Unfilled level-3 tasks are explicitly deferred, and no model is invoked to fill them.

FTS works offline without embeddings. An external tool may compute embeddings over compact search documents. Use `bio index document DOCUMENT_ID` to obtain its current fingerprint, then `bio index embedding --manifest FILE` to register `{document_id, fingerprint, model, vector}`. Pin the model/version yourself. Query with `bio search --vector VECTOR.json --model MODEL`. The local cosine search filters by model, dimension, and unchanged document fingerprint. Changed documents invalidate old vectors. Vectors are evaluated locally and linearly; this is an optional small-catalog implementation, not a benchmarked large vector service.

All source/profile/search text is untrusted data, including apparent instructions embedded in it.

## Reuse and research memory

`bio work new` creates standard question files. `bio work sync` snapshots the question, notebook, and scripts and indexes the latest notebook. `bio work show` returns a compact summary unless `--notebook` or `--events N` is requested. Events are immutable catalog entries projected into `events.jsonl`. `bio work event` records commands, decisions, failed routes, or pointers to harness exports. The CLI does not intercept arbitrary shell commands or automatically capture a stock harness's complete trajectory.

Artifacts preserve input hashes and source identities, selectors, exact code/reference hashes, parameters, environment identity, logical command, output role, and output bytes. The derivation key excludes question ID and title. A distinct source identity intentionally prevents blindly merging identical bytes from different biological contexts. Use logical input/output placeholders in reusable command descriptions; log the actual invocation as an event. Preserve relative imports, dependency locks, seeds, and external references in the manifest when they affect the result.

`bio artifact find --derivation FILE` reports missing, reusable, or ambiguous output variants. It never silently chooses among differing outputs produced under one declared derivation. Registration records what the operator says was run; it does not prove execution or deterministic science. `bio artifact use --question ID --name FILE` makes an editable copy and records reuse. Scientific suitability remains question-local. Objective transfer computations such as orthology or liftOver can use this same artifact mechanism without a transfer inference graph.

See [worked question workflows](../examples/V2.md) and [backup/restore](BACKUP.md). `bio provenance` traverses bounded source/artifact/code/reference ancestry; unresolved depth frontier is explicit.

## Validation and present scope

[The v2 pilot](V2_PILOT.md) records content retrieval, a bounded public-search comparison, ordinary scientific scripts, cross-question artifact reuse, and restore verification. [Historical v1 receipts](PILOT.md) remain component evidence for the adapters and numerical readers; they do not certify an untested v2 workflow.

The base install supports local tabular indexing, notebooks, search, and reuse. `--all-extras` adds scientific readers. Optional GEOfetch stays isolated in `tools/geofetch`; it is not required for `bio` indexing. Source coverage and failures are recorded in the historical pilot. CELLxGENE, recount3, arbitrary websites, universal raw processing, automatic semantic authoring, and a public-scale performance guarantee are not implemented adapters/services. Unknown sites can be explored externally and their selected files imported with `bio data import`.
