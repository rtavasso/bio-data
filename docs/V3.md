# V3: evidence retrieval before infrastructure expansion

The coding agent proposes biological mechanisms, checks external structured resources and primary papers, and analyzes public measurements with ordinary tools. `bio` preserves data, source context, searchable content, and reusable work. It does not decide biological truth or orchestrate an agent.

Start with `uv run bio --help` and the short [workflow guide](WORKFLOW.md). No model, credential, network, or hosted service is required for local use. Install scientific extras with `uv sync --all-extras` for the complete file-reader and test coverage.

## Question-local retrieval gaps

```sh
uv run bio work new "Can cell composition explain this expression change?"
# Use the returned question ID in place of QUESTION_ID.
uv run bio work gap QUESTION_ID \
  --need "Sample and cell-state annotations linked to the matrix" \
  --failed "Feature lookup found the matrix but does not establish cell identity" \
  --source-or-format H5AD \
  --likely-value "Would distinguish expression change from changing composition" \
  --possible-indexing-solution "Evaluate bounded obs metadata after inspecting the source" \
  --gap-key cell-state-annotations
uv run bio work gaps
uv run bio work gaps --since 2026-09-01T00:00:00Z --source-or-format H5AD
uv run bio work sync QUESTION_ID --summary "Recorded annotation gap; contrast remains unresolved"
```

For richer notes use `bio work event QUESTION_ID --kind retrieval_gap --payload gap.json`. Only `desired_information` and `why_current_tools_failed` are mandatory text. `question` must match the event, optional named fields are text, and arbitrary additional JSON survives. No schema migration is needed: these are existing immutable work events.

`bio work gaps` groups normalized source/format plus an explicit `gap_key`, or exact normalized need text. It counts distinct questions separately from repeated observations, returns up to three original examples with event/blob provenance, and shows author-reported value and proposed solutions. Ranking is recurrence, not a scientific score. It deliberately does not merge synonyms with a model. Use shared keys deliberately; unrelated failures should stay separate.

Reports accept `--question`, `--since` (timezone required), `--source-or-format`, `--limit` (1–100), and `--max-events` (1–100000). Time/question filters precede the bounded scan; source filtering follows it. `scan_complete`, `groups_truncated`, and counts expose incomplete coverage. Invalid legacy freeform events remain stored and are listed for manual review. Returned notes are untrusted content, never agent instructions.

## Optional enrichment and v2 compatibility

Levels 0–2 determine index completion: source/resource context, manifest inventory, structural inspection, and literal content as requested by the plan. `level: 3` remains a compatible plan value but does not enqueue or run semantic tasks. Agent-authored profiles and embeddings remain supported through existing explicit commands.

Status includes effective `state`, historical `recorded_state`, required-task frontier, stage counts, and optional `enrichment` coverage. Legacy semantic tasks and result blobs are preserved without retrying or mutating them. Recovery requeues interrupted required tasks. Real blocked/partial acquisition, extraction, or structural inspection still makes a job partial. Completion concerns the bounded plan, not exhaustion of public data or biological completeness.

No changes were made to source immutability, artifact derivation keys, interpretation revisions, or scientific extraction semantics. Old workspaces upgrade additively using the existing schema; v3 needs no new catalog tables. See [v2 component details](V2.md) and [backup/restore](BACKUP.md).

## Evaluation and expansion decisions

[Retrieval protocol](../benchmarks/retrieval/README.md) compares a strong runtime baseline (web, repository APIs, specialist indexes, ordinary file inspection) with the same capabilities plus deep local content. Count dataset/file plus a specific analysis, not papers, search hits, or additional encodings of one experiment. Four explicit judgments are required before calling an index-only opportunity valuable: relevance, independent information, ability to test an uncertainty, and willingness to analyze it.

[Prior recall protocol](../benchmarks/prior/README.md) seals model-only hypotheses before querying selected curated resources. It retains database-only, model-only, shared, conflicting, and unreviewed pairs. Runtime federation remains the default; curated annotations need citation/context checking too. There is no `bio prior` subsystem.

[Pilot results](V3_PILOT.md) drive the current decision: retain existing safe readers; improve source context and investigate cell annotation availability in actual questions before expanding formats. No speculative RDS/Seurat loader, raw-data workflow, biological graph, transfer engine, or global scientific score was added. A recorded gap proposes future work; it does not authorize running downloaded code or fabricate the missing data.
