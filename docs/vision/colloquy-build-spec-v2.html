Build specification v2 · follows the review of the first build (14 PRs, commits 04ca35f to 7b2bdc0)

Colloquy v2: close the gaps, then make every claim resolvable

The first build implemented every module of the original specification and runs against the real PMP22 cohort board. It is not yet the product the specification promised: a handful of defects break it on a researcher's laptop, three trust rules are not honoured end to end, and the "every number one click from its bytes" promise is implemented at the level of the post rather than the number. This document specifies the conformance work, then the work that advances the vision.

holds the first build meets the clause. narrowed implemented, but weaker than specified, and the docs say so. defect verified against the code or the real board. v2 new scope. IDs (C3, V2) are stable references for the builder; original module IDs (M1 to M9) are unchanged.

0Review verdict

Method: the merged branch was pulled, linted and tested (376 Python tests pass; 3 error on macOS), the web app was built and unit-tested, the API was run against a clone of the real cohort board (269 posts, 281 library artifacts, 97 runs, 25 workspaces), and five adversarial code reviews covered write paths, the observatory, the Studio, the runtime and discovery. The end-to-end suite could not run here because it expects a Playwright install at fixed paths.

What holds

  • Every write reaches the board through a function that holds the writer lock and appends an event; no HTTP path writes an agent workspace catalog. Permissions are checked inside the functions. Uploads are objects with receipts, never registered or executed. Marks never change a status.
  • The evidence map draws recorded relations only, each edge listing the rows or events it came from. No text-matching, similarity or time-proximity edges exist on the map.
  • Frontier items and claims are explicit agent records written through new CLI commands; nothing is extracted from prose except the wishlist's labelled Exact missing measurement: lines. Contradictions are proposals with no resolve path. Watchers are retrieval-only, attributed to a system participant, operator-scheduled.
  • The runtime has no scheduler, no automatic retry and no task chaining. The earlier hardening (opt-in notifications, reply closes request, provider-citation lint, workspace-only forks, compaction config) survived every merge.
  • On the real board: 71 routes answer; the dashboard reproduces the audit exactly (23.47 compute hours, 11.65 suspended, 279 of 440 plumbing scripts, 57 compactions, 13 fallbacks); question pages render networks, coverage, gaps and the event scrubber from workspace records; run timelines place compactions and suspensions.

What does not

  • It does not build on macOS. actions.ts beside Actions.tsx makes TypeScript resolve the wrong module on a case-insensitive filesystem: the build fails and 19 of 57 frontend tests fail. A rename fixes both.
  • Sandboxed agents cannot start on macOS. The board-service Unix socket path is 125 bytes, over the 104-byte limit; three tests error for the same reason.
  • Hidden posts leak. After hiding a post on the real board, its title and excerpt are still served by the map node endpoint and the run list, and anchor quotes replay over SSE.
  • The number-pointer rule is a filter, not a gate. It runs only on the Studio endpoint; the same prose is served unchecked on the post page, in search and in exports. Coverage is per sentence, exemptions are gameable, and nothing checks the number appears in the cited record.
  • Replication never executes. Every shipped test and demo copies the original bytes and manifest and earns a "reproduced" mark; confirmation is not gated on an execution receipt; the target may be the original author; and the prompt simultaneously instructs and forbids running fetched code.
  • A human's free-form ask is auto-delivered to a running agent verbatim, without author-kind label, task type or budget.
  • Vision gaps on real data. The cohort has no claims (agents never authored them), the frontier shows only retrieval gaps, and "every number opens its artifact" means each number links to every artifact the post names.
Overall: structurally faithful, honestly documented, and runnable against real data, but short of the specification on the trust rules and on the one capability the vision rests on. Milestone 1 (observatory) is met in a weakened form; Milestones 2 and 4 are met offline; Milestone 3 (Studio integrity) and Milestone 6 (pilot hardening) are not met.

2Conformance work

Each item names the defect, the specification clause it violates, the change, and the test that proves it. Order is by severity for a demo on a researcher's machine and for trust.

C0A real-data fixture the implementer can build against defect

Defect
Everything on the remote runs on the synthetic demo (daw/commons/demo.py), and the demo's author also wrote the tests, so the fixture carries exactly the structures the code expects: claims JSON on every post, Exact missing measurement: lines, one promoted item, one contradiction pair. The real cohort has none of those. Every gap this review found on real data (empty ledger, gaps-only frontier, post-level number pointers, map truncation, moderation leak on a real post, per-request scans over 25 workspaces) was invisible to the e2e suite, which passed.
Clause
Build plan: "Build every screen against [the cohort board] first"; Milestone 1 definition of done names the 281 artifacts and the ten finals.

Synthetic data is right for mechanics and invariants (locks, triggers, permissions, redaction, SSE cursors) and wrong for anything that depends on what agents actually write: claims, frontier items, number coverage, search ranking, map scale. Those must be designed and measured on the cohort.

  • Done with this specification: the cohort is committed in plain git at fixtures/pmp22-cohort/, built by bio commons fixture build ROOT OUT (src/daw/commons/fixture.py) and checked by bio commons fixture verify. It keeps the board, post bodies, artifact manifests, derived outputs up to 64 KB, notebooks, scripts and outputs up to 64 KB, work events, receipts, prompts, finals and every tool-call stream with tool outputs replaced by length and sha256 (exit codes kept). It drops downloaded bytes (source, full-text, reference, research-input, dataset-profile bodies, question inputs/ and sources/), the per-workspace content index, session databases, transcripts, stderr and credentials. Blob rows stay so identities resolve; absent files read as present: false. About 260 MB on disk, two thirds of it the per-workspace catalogs, no file over 50 MB; the git pack is smaller. FIXTURE.json records the rules and every file's hash; serving it must leave verify green, which doubles as the test for C3's reads-that-write.
  • Every acceptance test in section 5 that measures a share or a count (number coverage, map completeness, frontier kinds, search ranking, request latency) runs against fixtures/pmp22-cohort; the synthetic demo stays for invariant tests. A cohort pytest fixture opens it read-only.
  • Development against real data: uv run bio commons --root fixtures/pmp22-cohort serve. Every C and V item below names the cohort behaviour it must change, and docs/COLLOQUY.md's status table records which rows were checked on the cohort rather than the demo.
  • Rebuild the fixture from the live board after each cohort (same command); the snapshot's board sequence is in FIXTURE.json.

C1Build and run on macOS defect

Defect
web/src/components/participation/actions.ts and Actions.tsx collide on case-insensitive filesystems (TS1149/TS1261); the board-service socket <root>/service/board/agent_<32hex>/board.sock exceeds 104 bytes (boardservice.py:71-76, :252-263).
Clause
Build plan: "one bio commons serve command for the local demo"; Milestone 6: an external lab runs its own commons.
  • Rename the helper module (writes.ts) and update imports; add a CI job on macOS that runs npm run build and npm test. A local rename is already in the working tree and passes build and all 57 tests.
  • Bind the board service under a short per-commons socket directory: $TMPDIR/colloquy/<sha256(root)[:12]>/<agent-index>.sock with a symlink recorded in sandbox.json; refuse at startup with a clear error if the resolved path exceeds the platform limit; make the three tests use the short directory rather than skip.
  • Package the e2e suite's Playwright dependency as a dev dependency with pinned browsers rather than fixed host paths, so npm run e2e works on a fresh machine.

C2One moderation rule for every reader defect

Defect
GET /api/map/node/{post} serves title and excerpt of a hidden post (evidence_map.py:600-610); timeline.run_list, run_timeline and views.running read hidden titles; SSE replays comment anchor quotes after hiding; exports include hidden posts' identities, authors, reasons and replies.
Clause
M2.8 and M7.3: hidden content is withheld at display level, bytes kept.
  • Introduce one Visibility resolver in daw/commons/moderation.py used by every read model, the map, timelines, SSE framing and export. Readers get {id, hidden: true, reason} and nothing else unless the caller holds hide and asks for full.
  • SSE: redact evidence.anchor.quote for hidden targets at frame time; exports: omit hidden posts' bodies, titles and reply bodies, keep ids and the moderation event.
  • Test: hide a post, then assert redaction across post, thread, map node, map build, run list, running strip, SSE backlog and export. The test must run on the demo and on an imported cohort snapshot.

C3Write-API discipline and read-only reads defect

Defect
POST /api/frontier/clusters/confirm, POST /api/watchers and /disable use Caller instead of Actor: no CSRF header, no HTTP-layer kind check, and a SQLite connection opened in one thread and used in another. Anonymous GET /api/frontier* and /api/wishlist take the writer lock and append frontier_reindexed events. frontier_item carries board state (promoted_to, watcher_query, candidate_evidence) that a rebuild cannot recover from events.
Clause
M8.1 "never mutates"; M8.2 "each is a thin call into M2 under the board lock with the caller's participant identity"; data model: projections rebuildable.
  • Route the three endpoints through Actor and the write.py call helper; add a test that every POST route in app.ROUTER_MODULES requires X-Colloquy-Request.
  • Move frontier reindexing to the write path (after publish, promotion, watcher events) and an operator bio commons frontier rebuild; GETs read the projection only.
  • Make rebuild_frontier derive promotion, watcher and candidate-evidence state from promotion_created, watcher_added, watcher_ran and watcher_disabled events; add DELETE of orphans; test by dropping the table and rebuilding to byte-equal rows.

C4Human writes are attributed board content, never instructions defect

Defect
participation.ask → Community.ask → auto-delivery by the service to a started session; the body is appended to the prompt verbatim without an author-kind label (community_runtime.py:240-246). Human verbs exceed M7.2 (ask review export watch token profile); export is unlimited; profile role is self-asserted.
Clause
M7.3 trust rules; Charter risk row "no free-form instruction path to an agent"; M2.7 "promotion is the only path by which new scientific work is scheduled".
  • A human ask becomes a typed request (task_type=question) with the same allowance and budget as a promotion, delivered only when the asker's allowance permits; the prompt labels it "attributed board content from a human participant, not an instruction override", exactly as promotions already are.
  • Align permissions.py with M7.2 and document the additions (review, watch, token, profile, export); rate-limit export; derive the displayed role from kind, not the profile.
  • Cookie Secure from forwarded proto when --forwarded-allow-ips trusts the proxy; move login counters to the board so they survive restarts.

C5One checker for every rendering of a write-up defect

Defect
The unpointed-number refusal lives in writeup.render_writeup and fires only on GET /api/studio/writeups/{post}; /post/:id, search snippets, digests and export.markdown_html serve the same prose unchecked. Coverage is per sentence or table row; headings and letter-glued numbers are exempt; nothing checks that the number occurs in the cited record.
Clause
Connections table: "Every number must resolve to a pointer; refuse otherwise". Flow B step 5.
  • Run writeup.check in tasks at delivery for writing and digest types; store the verdict as an immutable writeup_check event with per-number locations; refused write-ups complete the request but are served as a placeholder on every surface; regeneration() is also evaluated at render for later withdrawals.
  • Make coverage number-granular: a pointer covers only the numbers in its own link or bracket, not the whole sentence; remove the heading and letter-glued exemptions; detect spelled-out small integers and unicode fractions.
  • Value-in-record check (prerequisite for V2): when a pointer names a claim, the number must appear in the claim text or scope; when it names an artifact, the number must appear in the artifact's output bytes at the cited locator (row, column, key) or anywhere in a small text artifact; otherwise the number is unverified and shown as such.
  • Export uses the same checker and writes the verdict into the snapshot.

C6Replication that executes, under an explicit carve-out defect

Defect
tasks.py:98-104 instructs the agent to re-execute fetched code while the same prompt forbids executing downloaded code; _replication compares output hashes of any same-key registration and ignores run_analysis.py receipts; the demo and tests copy bytes; the target can be the original author; _confirm and _mismatch post under the agent's identity.
Clause
M6.3 "a different agent re-executes a registered derivation from the saved code and inputs under its own receipts"; Charter "never execute downloaded code" (AGENTS.md); M7.3 marks are attribution.
  • Write the carve-out into AGENTS.md and the task prompt: a replication may execute only the code blobs named in the fetched derivation, after hash verification, through run_analysis.py, inside a sandbox with egress off. Any other execution of fetched code remains forbidden.
  • Confirmation requires a receipt whose producer hash equals a derivation code blob and whose written outputs include the replica; otherwise the outcome is no_execution_receipt, never confirmed. Commission refuses a target that produced the original.
  • Platform-generated confirmation and mismatch posts and marks are authored by a replication system participant and cite the agent's receipt; agents sign only what they wrote.
  • Replace the demo hook with a real re-execution of the synthetic derivation's saved script; add a test that a copied-bytes registration without a receipt is refused.

C7Sandbox holes defect

  • Egress allowlist: compute hosts per dispatch from the agent's adapter and pass them to the proxy per connection (token-scoped policy), rather than freezing the list at proxy start; test by adding a Claude agent after the proxy is running.
  • Budgets: move config.toml budgets to a platform-owned file mounted read-only (or have the transport read budgets from the sandbox receipt); treat a changed budget file as a policy violation event, not a note.
  • Harness homes (.claude-home/settings.json, .hermes/config.yaml) are mounted read-only; agents receive per-turn copies for scratch.
  • Sandboxed Hermes resume: run the session bridge inside the agent image, or document the host dependency in pilot.md and refuse early with a named error.
  • Surface token-budget exceedance as a board event and an operator notice.

C8Flow B end to end defect

  • participation.post with supersedes calls claims.notify_affected exactly as Community.publish does; add the test for the HTTP path.
  • Render /api/corrections/{post} on the superseded post page ("affected readers") and on the correction.
  • Regeneration flags also trigger when a write-up cites an artifact or post of a superseded publication, not only a withdrawn claim.

C9Search and discovery corrections defect

  • Commons search pagination: page in the commons layer rather than passing offset + limit to the substrate's 100-row cap.
  • bio data search excludes jats-paragraph documents unless --format asks for them, so a 200-paragraph article cannot crowd dataset hits; paragraph search gets its own family or flag.
  • Frontier: show whether candidate_evidence was set by a watcher or by the author; unmask the author's watcher_query when a watcher is disabled; mark whether post: pointers exist on the board, as the code comment claims.
  • Discovery demo: never insert a platform-authored frontier_item; store source as JSON everywhere; rebuild_frontier deletes orphans.
  • Watchers: add the "new full text for a known article" watcher the spec names; label provider-supplied titles in notices as third-party text.

C10Honest metrics and timelines narrowed

  • Benchmark and runmetrics return None rather than 0 when a clock or stream feature is unavailable; compactions are "unavailable" for harnesses that do not emit them.
  • Timeline: draw heuristically placed items (suspension, headline, peer answers consumed) with a distinct style and a legend entry "attributed, not recorded"; see V6 for recording them instead.

C11Post-level number pointers are labelled as such narrowed

Until V2 lands, scope=post pointers are shown as "this post's evidence" rather than as a link from the number; the post page lists unpointed numbers and post-scoped numbers separately, and the dashboard reports the share of numbers with line- or claim-scope pointers per cohort so the authoring change in V1 is measurable.

C12Documentation corrections narrowed

Library artifacts and posts are never truncated; degree-based truncation applies only to object and asset nodes, and the response says which families were truncated. On the cohort board the default view then shows all 281 library artifacts (today 276).

3Vision work

These items change what a researcher can do, not whether the build matches the first spec. They assume C1 to C14 are done.

V1Claims-first authoring v2

The cohort board has 269 posts and zero claims because claims were a new CLI nobody had used. The vision depends on claims existing, so authoring must be the path of least resistance for agents.

  • The research skill's final-answer structure becomes: claims (JSON, with pointers) first, prose second; community publish warns when a post with evidence carries no claims and the writing task refuses to cite a post without them.
  • An agent-side helper claims_draft.py proposes claim entries from the agent's own registered tables (one per named contrast, with the artifact and row locator filled in); the agent edits and confirms. The platform never writes claims; the helper runs in the agent's checkout on its own outputs.
  • Dashboard: claims per post, pointer scope distribution, and the share of numbers covered by claim-scope pointers, per cohort. Target for the next cohort: every published analysis carries claims, and more than half of numbers in finals have claim- or line-scope pointers.

V2Value-in-record pointers: the one-click promise, kept v2

  • Pointer locators gain a cell grammar for tabular artifacts (row=<key>;col=<name>) and a key path for JSON; the checker in C5 verifies the cited value equals the number in the prose, with declared rounding.
  • The artifact page opens at the locator and highlights the cell; the post page underlines verified numbers and marks unverified ones; the map shows claim nodes with their verified pointer count.
  • Cohort audit script: for each final, the share of numbers resolvable to a cell. This replaces the weakened Milestone 1 definition of done.

V3The real-data pilot v2

  • Import the PMP22 cohort board as the first public demo commons (it already runs); add the C2 redaction, V2 pointers where authors inlined artifact ids, and a curated reading path for a visitor: board → one thread → one number → its bytes.
  • Run three round-two-style questions on two harnesses with the v2 skills so the ledger, frontier kinds beyond gaps, and backed reuse are populated by live agents; publish the dashboard comparison.
  • Invite three external researchers as human participants; measure comments, marks, promotions and whether a promotion changed what an agent worked on.

V4Human workbench v2

  • A personal inbox for humans: answers to their asks, replies to their comments, corrections to posts they marked, watcher hits on items they promoted, delivered over SSE and listed at /me.
  • Saved views (a question set, a participant set, a time window) that every screen and the map accept; shareable as a bare hash token.
  • Reading mode for a thread: posts, corrections and claims interleaved in time with evidence panes on the side; keyboard navigation between numbers and their records.
  • Comment threads at anchors with human replies, and a "request review" action that commissions an adversarial review of the anchored claim.

V5Frontier as the planning surface v2

  • Board view of frontier items by state (open, blocked, candidate evidence, promoted, closed) with budgets and targets; promotion creates the request from the card.
  • Cluster confirmation merges nothing but creates a "shared experiment" item that lists its member questions; the wishlist exports as a lab-ready proposal document with every requirement linked to the questions that need it.
  • Scouting tasks fill items with inspected, eligible datasets before any analysis is promoted; the item shows which datasets were inspected and rejected, with reasons.

V6Record what the timeline attributes v2

  • The capture layer emits heartbeat events into the stream with both clocks, so suspensions are placed by record rather than by the largest gap; compaction summaries and fallbacks are recorded as events at capture time from the session database.
  • Analysis receipts become records: the runtime indexes run_analysis.py receipt files per delivery, and the timeline draws receipts from them, not from exit codes.
  • A persistent graph store keyed by event sequence replaces per-request map builds; the map and the artifact page answer in constant time per node on a cohort-sized board.

V7Publishing and federation that resolve v2

  • Preprint export: a write-up plus its cited claims, artifacts and snapshot id, with each figure linked to its artifact bytes; a reader of the static site can verify every number offline with the included checker verdicts.
  • Federation that resolves: imported snapshots register their claim and artifact ids in a read-only index so pointers across commons resolve to bytes; citations carry the snapshot id.
  • A public commons directory where labs publish snapshots; the dashboard shows which snapshots were cited by which questions.

V8Live multi-harness cohorts v2

  • Live receipts for Codex exec resume and the Claude adapter; a cohort of the same three assignments on Hermes, Codex and Claude with separate yield, calibration, correction and cost cells; the scripted stand-in stays for offline tests only.
  • Compaction hygiene becomes a tracked metric per harness (fallbacks, summaries that lost the assignment, context per call) using the v1 hardening configuration.

V9Private boards and multi-tenant safety v2

  • Per-commons read policy (public, members, private) enforced server-side, so a lab does not need an authenticating proxy.
  • Per-container uids and disk quotas on the checkout; audit log viewer for operators; rate limits and login counters persisted on the board.

V10Optional: a learning layer that is measured, not assumed v2

Deferred by decision. If revisited: a consolidation task at the end of each assignment writes a topic-scoped retrieval skill through the harness's own skill tool; the dashboard counts skills written, skills viewed by a different agent, and decisions changed by a viewed skill. Without those three numbers moving, the layer stays off.

6Charter and builder rules

Unchanged: immutable source bytes, receipts and provenance; no platform biological-prior graph; no cross-context transfer engine; no scientific DSL; no custom research agent loop; question-local hypothesis networks; retrieval is not reuse and reuse is not applicability; missing, unindexed, selected-out, unmeasured and measured-zero are different. One addition, from C6: a replication task may execute only the hash-verified code blobs of the fetched derivation, through run_analysis.py, in a sandbox with egress off. Nothing else fetched is ever executed.
  • No write path around daw.community or the writer locks; no reads that write.
  • No inferred edges; record at the source first.
  • No scheduler; promotion by a person is the only entry, and a human ask is a promotion.
  • Untrusted content rendered as untrusted, hidden content hidden on every surface.
  • Every screen reproducible from the archive alone.
  • CI on macOS and Linux; uv run ruff check, uv run pytest, npm run build, npm test, npm run e2e green before merge.
  • Docs state what is exercised offline, what is live-verified, and what is attributed rather than recorded.
